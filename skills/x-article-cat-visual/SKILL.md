# X 文章布偶猫智能配图 Skill（V4.0｜会话整合版）

## 目标

针对一篇 X 文章，**直接制作一张**与文章观点一致、具有明确行动目的的高质量插画。同一只猫，不同的动作与故事。优先执行用户要求；不要在素材完整时反复提问，也不要只回复生图提示词来代替出图。

**角色身份**：`assets/ragdoll-ip-reference.jfif` 为本会话用户上传的原始 IP 参考图。若当前请求额外提供更新版参考图，以新图为最高优先级。不要把历史生成图错误当成原始标准。

**辅助文档**：
- `references/visual-spec.md`：角色、构图、主题解析与禁止事项
- `references/session-history.md`：当前会话已画过的故事和避免重复的镜头
- `scripts/export_image.py`：等比例裁切/缩放成目标尺寸，并核验像素

## 用户输入

```text
图片类型：封面图 / 文章内插图
文章标题：...
文章正文：...
指定插图段落（可选）：...
特殊要求（可选）：...
IP 参考图片（可选）：新上传图；否则用 assets/ragdoll-ip-reference.jfif
```

标题与正文可短可长。默认一张图。封面概括全文，内插图聚焦一处知识点。若用户明确指定画面、比较方式、衣着、文字等，优先遵守且保持 IP 特征。

## 核心决策流程

1. **抽取语义**：用一句话确定文章的“核心变化/矛盾/结论”，识别领域、关键实体、可视化对象与情绪；避免只按标题堆道具。不要杜撰文章没有的事实、数据、软件功能或 Logo。
2. **选择视觉叙事**：将抽象观点变成有因果关系的具体事件。先定 `行为目的 + 身体动作 + 互动对象 + 情绪 + 镜头`，后搭场景。
3. **选择动作**：探索、检查、推动、翻找、追踪、修复、比较、攀爬、转身、跨越或日常行为；强度由文章情绪决定（严肃分析低动态、实用教程中动态、突破发现高动态）。遵守猫科解剖和接触重心。
4. **防止重复**：比对 `references/session-history.md` 和可访问的历史图片。至少改变动作、场景、相机角度、互动对象、主体位置、情绪中的三个维度。警惕连续复用**云端跳跃、霓虹科技卡片、同一种左暗右亮对比、桌前坐姿**。
5. **选择图像模式**：
   - **封面图**：5:2，最终 **2000×800 PNG**（备选 1920×768）；宽幅电影构图，主体和关键互动对象避开最外围约 10%，主题一眼能懂。
   - **正文插图**：16:9，最终 **1920×1080 PNG**；突出一条具体知识点，背景更简洁。只有用户明确要求时改 3:2、4:3。
6. **处理文字**：默认不加任何文字。用户要求加文字时，用简短且可校验的中文标题/关键词（一般标题一行 + 每侧一个短标签即可）；文案应来自用户内容，不加虚构 Benchmark 或数字。文字必须清晰、正确、不过密；若生图文字错字，使用准确排版工具重做或重新生成。
7. **生成图片**：使用可用生图工具，传入上传的原始参考图（若工具支持），写清猫的身份特征、动作目标、环境、布局、镜头、光线、文字要求及安全边距。工具无法访问参考图时明确说明，不能假称角色完全一致。
8. **真实尺寸导出**：生图平台输出尺寸不一定恰好是标称尺寸。若不精确，可用 `scripts/export_image.py`；须先检查裁切是否会损失猫脸、动作或主要对象。不能非等比例拉伸。**实际读取导出文件宽高**后，才可声称合格。
9. **质检和交付**：依次核对外貌、自然动作、文章语义、画面整洁、文字准确、真实比例/像素；每次交付一张图片，有可访问文件时给出真实文件链接。若工具不支持尺寸导出，应如实注明原始像素，不能虚报。

## 为生图工具组织指令

按以下固定框架将文章语义填入，不要把本文整份照抄给图片模型：

```text
以用户上传的原始蓝眼睛奶油白布偶猫为唯一主角原型，圆润幼态面容、粉鼻、浅灰棕耳尖/面部外围/蓬松尾巴，高品质长毛，严格保持同一只猫。
主题：[文章最重要的可视化结论]
叙事：[猫为什么行动、正在如何触碰/操作某个对象、造成什么变化]
动作：[身体姿势、方向、接触点、重心、尾巴动态、表情]
场景：[与主题直接相关的空间与少量道具]
镜头：[景别、相机高度/角度、光线、左右/前后层次]
配色：#8FC9F5 天空蓝、#B9D9F5 柔和浅蓝、#FFF7ED 奶油白、#F7F2EC 暖白、#B5A6A2 灰棕；少量暖金/青/紫点缀。
画风：梦幻治愈系、电影级高品质 3D 动画、细腻真实长毛、柔和全局照明和自然轮廓光。
布局：[封面 5:2 横幅 / 内插图 16:9]，为裁切预留主体安全区。
文字：[默认完全无文字；若用户要求则写出必须准确出现的极简文本]
避免：同质化的电脑桌/正面端坐/云端跃迁、过量悬浮科技图标、变种猫脸、额外肢体、错误品牌标识、难以辨认的文字、纯装饰性摆拍。
```

## 出图与导出

在具备本地 Python 与 Pillow 的环境中：

```bash
python scripts/export_image.py --input input.png --output cover.png --type cover
python scripts/export_image.py --input input.png --output illustration.png --type inline
```

该工具只负责**可控范围内的等比例裁切与高质量缩放**；大幅比例不符会拒绝盲裁，要求重新构图/扩图。无需工具或不具备像素处理能力时，不得声称已处理。

## 重要边界

- 无参考图片时，只有用户允许纯文字角色描述才据此生成；否则说明角色一致性无法验证。
- 不虚构“已测得 2000×800”“图中中文百分百准确”等结论。
- 图片模型的生成不是精确图表/真实代码渲染的可靠方式。涉及数据、代码和复杂标注，应使用精确排版和真实来源素材。
- 外部站点和产品功能可直接依用户提供的正文作视觉转译；如需核实事实，先独立查证，不把文章宣传语当已验证真相。
