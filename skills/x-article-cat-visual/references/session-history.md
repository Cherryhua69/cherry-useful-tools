# 当前会话已有视觉主题｜防重复参考

本文件根据用户在本会话中提出的文章和可访问的生成图整理。它记录的是**构图倾向与叙事模式**，不是每张图的全部细节，也不作为替换原始猫咪照片的身份依据。

| 文章主题 | 已使用的大致视觉故事 | 未来优先改变的元素 |
|---|---|---|
| Dots vs Muse AI 助手 | 云中桥梁，一侧个人陪伴/记忆、一侧自动化任务卡片，猫咪走向任务流程 | 换实体生活场景、低机位和真实工具互动 |
| REA 逆向工程 | 猫伸爪触碰高空软件调用节点，未来感三维设备与漂浮 UI | 更微距的内部结构拆解、较少浮屏 |
| Hallmark 去除 AI 味 UI | 猫推动/拖动网页视觉素材，让粗糙网页变精美 | 换实际浏览器诊断/排版网格场景 |
| 不打卡公司的隐形边界 | 职场通勤、时钟、领导观察和多个小场景拼贴 | 换单帧叙事、避免多只猫同画面混淆角色 |
| claude-mem Agent 跨会话记忆 | 猫悬空抓取记忆模块，云端任务入口连接 | 换室内资料整理或新旧工作台交接 |
| 如何坚持发帖 | 猫穿蓝色卫衣在桌前写灵感笔记，创作清单和灵感泡泡 | 换户外探索素材/抓取新闻线索等动作 |
| CodeGraph（无字） | 左侧文件堆/搜索，右侧关系图谱，猫向右跃迁 | 用更明确的交互画面、换视角和姿态 |
| CodeGraph（带字） | 左右对照、两只同一 IP 不同状态，标题“vibe coding 的正确姿势”、短标签 | 若继续同主题，避免同样左右飞跃；可采用俯视迷宫或功能因果链 |

注意：同一图片中的两只同款布偶猫可作为“对比时间线”的艺术手段，但**默认优先一只猫**，以降低角色身份混乱。比较场景中可用一个角色跨越两处的动作或镜头内因果代替复制角色。

防重复不是严禁所有云端、图谱或对比构图，而是**连续作品至少在三个设计维度真正变化**：行为、场景、机位、主体位置、互动对象、情绪。
